# Estado del proyecto — 19 Jun 2026

## 🚧 Issues conocidos (pendientes)

### 1. Scanner SEC no captura forms variados (10-K, 10-Q, S-8, DEF 14A)
- **Causa**: `ScanPipeline.scan_ticker()` solo procesa los N filings más recientes por fecha. Si un ticker tiene muchos 8-Ks recientes (ej. SNBR con 149 8-Ks por bancarrota), los 10-K, 10-Q y otros forms quedan fuera del límite de 30.
- **Impacto**: Las categorías Financials, Registrations, Proxies aparecen vacías para tickers con muchos 8-Ks recientes.
- **Posible fix**: Hacer dos pasadas en el scan: (1) forms críticos para dilución, (2) un filing de cada tipo de form para la vista agrupada. O aumentar `max_filings` significativamente.
- **Archivos**: `backend/pipeline.py:87` (default max_filings=10), `backend/main.py:178` (scan endpoint)

### 2. Sin títulos descriptivos en filings
- **Causa**: El `summary` del filing se llena con keywords del parser (`matched_keywords`). Si no hay keywords, queda `None` y la UI muestra "8-K filing" genérico.
- **Fix parcial aplicado**: Se agregó `FORM_DESCRIPTIONS` en `pipeline.py` como fallback (ej. "Form 8-K — Current report").
- **Pendiente**: Extraer títulos reales del HTML del filing SEC (8-K items, etc.) para tener headlines como "Sleep Number Corporation Receives Nasdaq Delisting Notice...".
- **Archivos**: `backend/pipeline.py` (FORM_DESCRIPTIONS dict + summary fallback)

### 3. Parseo de forms no-estándar
- **Causa**: `sec_parser.py` está optimizado para S-3, 424B5, 8-K. Forms como 10-K, 10-Q, S-8, DEF 14A tienen estructuras HTML que el parser no maneja bien.
- **Impacto**: Esos forms no se guardan aunque el scan los intente procesar.
- **Posible fix**: Extender `sec_parser.py` para manejar múltiples formatos de HTML SEC.
